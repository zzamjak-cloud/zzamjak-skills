# 정기 게시 리듬과 주요 시점

목표는 "많이"가 아니라 **끊기지 않게**다. 주 1~2회, 한 번에 15분 이내가 기본이다.

## 고정 리듬 (전 프로젝트 공통)

| 주기 | 언제(한국 시간) | 무엇 | 채널 |
|---|---|---|---|
| 매주 토 | 토 오전~오후 | `#screenshotsaturday` — 진행 중인 게임/도구 GIF 1개 | X (+ 엔진 서브레딧 주간 스레드가 있으면) |
| 매주 수 | 수 밤 | 작업 중 화면 1장 + 한 줄(`#WIP`·`#gamedev`·`#b3d`) | X |
| 매주 1회 | 주중 아무 때 | 쇼츠 1개 (기존 녹화 재가공도 OK) | YouTube Shorts·TikTok·Reels |
| 격주 | 화~목 오전 | 개발 이야기·배운 점 | LinkedIn |
| 매월 첫 주 | 월~화 | 지난달 결과 정리(새 프로젝트·업데이트 묶음) | LinkedIn·X 스레드·디스콰이엇 메이커 로그 |
| 매월 | 아무 때 | 커뮤니티 댓글 활동 10개(홍보 링크 없이) | Reddit·포럼 |

## 이벤트 시점 (발생 시)

| 계기 | 무엇 |
|---|---|
| 프로젝트 첫 공개 | `schedule.md` 3주 런칭 플랜 |
| 새 버전 릴리스 | 포럼 스레드 답글 + X 1개 + 변경점이 시각적이면 쇼츠 |
| GitHub 스타·다운로드 이정표(100·500·1000) | 감사 글(X·LinkedIn) |
| 엔진/툴 새 버전 출시 주간(Blender·Unity·Godot) | "새 버전 호환 확인" 글 — 검색·관심이 몰림 |
| 게임잼·축제 기간(GMTK Jam, Godot Wild Jam, Steam Next Fest 등) | 게임 프로젝트 개발 일지·쇼츠. 날짜는 공식 사이트에서 확인 후 등록 |
| 연말(12월) | 올해 만든 것 총정리 스레드·영상 |

외부 이벤트 날짜는 추측하지 않는다. 웹에서 확인한 날짜만 캘린더에 넣고, 확인 못 하면 `(날짜 확인 필요)` 할 일로 남긴다.

## 캘린더 등록

**1순위: Google Calendar MCP**(`claude.ai Google Calendar`). 기본 캘린더(zzamjak work)에 제목 `[홍보]` 접두어, `colorId 3`(보라), `availability FREE`, 팝업 알림으로 `create_event` 한다. 반복은 `recurrenceData: ["RRULE:..."]`. 등록 전 `search_events("홍보")`로 같은 일정이 있는지 확인해 중복을 피한다. 도구가 안 보이면 `~/.claude/settings.json`의 `deniedMcpServers`에 막혀 있는지 확인한다.
QuickNote 스케줄러는 반복이 없어 런칭 같은 단발 일정에만 쓴다.

**대안: .ics 파일**

`~/dev/promo/calendar.json`에 일정을 모으고 `scripts/make_calendar.py`로 `.ics`를 만든다. 사용자는 `.ics`를 더블클릭해 캘린더에 가져온다.
각 일정 설명에는 **무엇을 올릴지 + 초안 파일 경로**를 넣는다. 알림이 오면 사용자가 Claude에게 "<프로젝트> 이번 주 쇼츠 만들어줘"처럼 요청하면 된다.
처음 가져올 때 캘린더 앱에서 전용 캘린더("프로젝트 홍보")를 만들어 그곳으로 가져온다. 일정을 바꾸면 json을 고치고 ics를 다시 만든 뒤, **전용 캘린더를 지우고 다시 가져온다**(앱에 따라 다시 가져오기가 갱신이 아니라 중복이 될 수 있음).
ics를 직접 `open`해 가져오지 않는다 — 사용자의 캘린더에 쓰는 일이라 사용자가 한다.
